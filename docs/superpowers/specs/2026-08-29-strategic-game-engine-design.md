# Движок текстовых стратегических игр для учебных занятий

Дата: 2026-08-29
Статус: дизайн согласован, реализация не начата

## 1. Задача

Преподавателю нужен инструмент, чтобы проводить со студентами штабные
стратегические игры: команды принимают решения за стороны конфликта, модель
считает последствия, после игры проводится разбор полётов.

Строим две вещи сразу: **движок**, который описывает игру декларативно, и
**одну эталонную игру** на нём. Движок оправдан тем, что следующая тема курса
не должна означать новый код.

## 2. Область работ

Работа разбита на три этапа. Эта спека подробно описывает этап 1; архитектура
и контракты заданы сразу для всех трёх, чтобы этапы 2 и 3 не потребовали
переделки.

| Этап | Содержание |
|---|---|
| 1 | Ядро, схема сценария, валидатор, три экрана, шаблонный нарратив, эталонный сценарий, сборка `.app` |
| 2 | Свободный ввод с распознаванием намерения, LLM-нарратив, экспорт разбора |
| 3 | Браузерный редактор сценариев |

**Не входит в работу вообще:** сетевой многопользовательский режим,
аутентификация, серверное развёртывание, редактирование состояния мира
ведущим вручную (откат раунда — входит, ручная правка треков — нет).

## 3. Решения, принятые при проектировании

| Решение | Причина |
|---|---|
| Игра идёт на одной машине по очереди (hot-seat) | Так проходит занятие; снимает сеть, сервер и аутентификацию целиком |
| Ядро — чистая функция без ввода-вывода | Тестируемость, переносимость между интерфейсами |
| Сессия хранится как журнал приказов, состояние — производное | Даёт откат, воспроизводимость и материал для разбора одним решением |
| Числа считает детерминированное ядро, LLM только пересказывает | Разбор полётов возможен, баланс контролируем |
| Формулы сценария — строки в ограниченном языке выражений | Сценарий остаётся данными: чужой файл безопасно открыть |
| Приказы одновременные | Порядок передачи компьютера не должен давать преимущества |
| Сделка, предложенная в раунде N, рассматривается в N+1 | Иначе итог зависит от того, кто раньше сел за компьютер |
| Свободный текст замысла сохраняется с этапа 1, распознаётся с этапа 2 | Данные для разбора собираем сразу, LLM подключаем на устоявшейся схеме |
| Целевая ОС — macOS, код кроссплатформенный | Сегодня раздаём на Mac; сборка под Windows не должна требовать переписывания |

## 4. Архитектура

```
scenarios/*.yaml ─► загрузчик + валидатор ─► ScenarioSpec
                                                 │
приказы команд ──► resolve(spec, state, orders, rng) ──► (state', события)
                                                 │
                                       журнал сессии (JSON на диске)
                                                 │
                          FastAPI ─► экраны: пульт / команда / проектор
                                                 │
                                 нарратор: шаблоны | LLM (этап 2)
```

Слои и их зависимости строго направлены вниз: `web` → `session` → `core`;
`narrate` зависит только от типов событий `core`. Ядро не импортирует ни
FastAPI, ни файловые модули, ни клиент Anthropic.

### Структура проекта


## 5. Модель предметной области

**Трек** — именованная числовая величина с границами и признаком видимости
(`public` виден всем, `private` только владельцу). Треки описаны один раз и
есть у каждой стороны. Примеры: бюджет, вооружённые силы, легитимность,
разведка.

**Мировые треки** — общие для всех: напряжённость, внимание мирового
сообщества. Всегда публичны.

**Сторона (faction)** — команда: набор значений треков, тайный брифинг, тайные
цели с весами очков.

**Отношения** — значение на каждую неупорядоченную пару сторон плюс набор
действующих статусов (пакт, эмбарго, конфликт) со сроком действия.

**Действие** — карточка из каталога сценария: стоимость (формулы), условие
доступности, тип цели (нет / другая сторона), эффекты, необязательная таблица
рисков, видимость (`open` / `secret`), шанс раскрытия автора, список действий,
которые ему противодействуют.

**Приказ** — выбранное командой действие с параметрами и свободным текстом
замысла. У действия есть цена в очках действий (`ap`, по умолчанию 1); сумма
`ap` всех приказов команды за раунд не должна превышать `meta.action_points`.
Одно и то же действие можно заказать дважды, если хватает очков и ресурсов.

**Сделка** — предложение другой стороне: передача ресурса или заключение
статуса на N раундов. Идентификатором установленного статуса становится `id`
сделки, по нему на статус ссылаются выражения. Рассматривается адресатом в
следующем раунде.

**Событие модели** — плановое (по номеру раунда) или триггерное (по условию на
состоянии), с эффектами и текстом.

**Запись события** (`Event`) — то, что попадает в журнал и в нарратив: автор,
тип, дельты по трекам, применённая формула, результат броска, **аудитория**.

## 6. Схема сценария

Один YAML-файл. Это язык конструктора; редактор этапа 3 — форма над этой же
схемой.

```yaml
schema_version: 1

meta:
  id: meridian
  title: "Кризис в Меридианском заливе"
  rounds: 8
  action_points: 3

tracks:
  budget:     { title: "Бюджет",        min: 0, max: 200, visibility: public }
  army:       { title: "Вооружённые силы", min: 0, max: 100, visibility: public }
  legitimacy: { title: "Легитимность",  min: 0, max: 100, visibility: public }
  intel:      { title: "Разведка",      min: 0, max: 100, visibility: private }

world:
  tension: { title: "Напряжённость", min: 0, max: 100, start: 30 }

factions:
  - id: astoria
    title: "Астория"
    start: { budget: 120, army: 60, legitimacy: 55, intel: 40 }
    briefing: |
      Тайный вводный текст, который видит только эта команда.
    goals:
      - { id: keep_strait, title: "Удержать пролив", when: "world.tension < 60", score: 30 }

relations:
  default: 0
  pairs:
    - { a: astoria, b: borea, value: -20 }

actions:
  - id: mobilize
    title: "Мобилизация"
    description: "Наращивание группировки у границы."
    ap: 1
    cost: { budget: 20 }
    requires: "self.army < 90"
    visibility: open
    effects:
      - { self: army,        delta: "10" }
      - { self: legitimacy,  delta: "-3" }
      - { world: tension,    delta: "5" }

  - id: cyber_op
    title: "Кибероперация"
    target: faction
    cost: { budget: 15, intel: 10 }
    requires: "self.intel >= 10"
    visibility: secret
    reveal_chance: 0.35
    countered_by: [ cyber_defense ]
    risk:
      - { p: 0.5, title: "успех",    effects: [ { target: budget, delta: "-15" },
                                               { relation: [self, target], delta: "-10" } ] }
      - { p: 0.3, title: "частично", effects: [ { target: budget, delta: "-5" } ] }
      - { p: 0.2, title: "провал",   effects: [ { self: intel, delta: "-10" } ] }

  - id: cyber_defense
    title: "Киберзащита"
    ap: 1
    cost: { budget: 10 }
    visibility: open
    counter_multiplier: 0.25          # сколько остаётся от эффекта погашенной атаки
    effects:
      - { self: intel, delta: "5" }

deals:
  - { id: transfer, title: "Передача бюджета", kind: resource, track: budget }
  - { id: pact,     title: "Пакт о ненападении", kind: status, duration: 3 }

world_dynamics:
  - { world: tension, delta: "-3" }
  - { all: budget,    delta: "5 + self.legitimacy * 0.05" }

events:
  - id: oil_shock
    when: "round == 4"
    title: "Скачок цен на энергоносители"
    text: "Мировые цены резко пошли вверх."
    effects: [ { all: budget, delta: "-10" } ]
  - id: un_pressure
    when: "world.tension > 70"
    once: true
    title: "Давление международного сообщества"
    effects: [ { all: legitimacy, delta: "-5" } ]

end:
  when: "round > meta.rounds or world.tension >= 100"
  scoring: "self.legitimacy + self.army * 0.5 + self.budget * 0.2"
```

### Язык выражений

Выражения — строки, вычисляемые собственным интерпретатором: `ast.parse` в
режиме `eval` плюс белый список узлов (числа, имена из контекста, арифметика,
сравнения, `and/or/not`, тернарный оператор, вызовы только разрешённых
функций). Всё прочее — синтаксическая ошибка сценария, не исключение времени
выполнения.

Контекст: `self.<track>`, `target.<track>`, `world.<track>`, `round`,
`meta.rounds`, `rel(a, b)`. Функции: `min`, `max`, `abs`, `round`, `floor`,
`ceil`, `clamp`.

Эффект — это одна из четырёх форм, и ровно одна: `{ self: <трек> }`,
`{ target: <трек> }`, `{ world: <трек> }`, `{ all: <трек> }` (всем сторонам)
или `{ relation: [self, target] }` — изменение отношения между парой. Поле
`delta` обязательно во всех формах.

`eval` и `exec` не используются нигде.

### Валидатор

Команда `sgame validate scenario.yaml` проверяет и печатает ошибки с номером
строки:

1. ссылки на несуществующие треки, стороны, действия;
2. вероятности в `risk` не в диапазоне `[0, 1]` и не в сумме 1;
3. синтаксис каждого выражения и допустимость имён в его контексте;
4. взаимные ссылки в `countered_by` (цикл длиной 1 запрещён);
5. стартовые значения вне границ трека;
6. недостижимые цели (условие ссылается на несуществующий трек).

Каждая ошибка — отдельная строка вида `meridian.yaml:42: действие "cyber_op"
ссылается на неизвестный трек "cyberdef"`.

### Версия схемы

`schema_version` обязателен. Загрузчик знает текущую версию и набор миграций;
файл старой версии либо мигрируется в памяти, либо отклоняется с указанием,
какой версии он требует. Файл будущей версии отклоняется всегда.

## 7. Разрешение раунда

`resolve(spec, state, orders, deals, round_no, seed) -> (state', [Event])` —
чистая функция. Порядок фаз фиксирован; это делает результат объяснимым для
студентов.

1. **Валидация приказов.** Лимит очков, наличие ресурсов, `requires`,
   допустимость цели. Отклонённые приказы не применяются и попадают в журнал
   с причиной — команда увидит её в следующем раунде.
2. **Оплата.** Списание стоимости всех принятых приказов.
3. **Сделки.** Предложения прошлого раунда: принятые исполняются (перевод
   ресурса, установка статуса), отклонённые и просроченные закрываются.
4. **Противодействия.** Если сторона B заказала действие, указанное в
   `countered_by` действия стороны A, направленного на B, все числовые дельты
   действия A умножаются на `counter_multiplier` контрдействия (по умолчанию
   0). Бросок риска при этом всё равно выполняется — иначе порядок обращений к
   генератору зависел бы от чужих приказов и ломал воспроизводимость. Обе
   стороны получают запись о столкновении; для атакующего она означает, что
   его действие ждали.
5. **Эффекты и броски.** Действия без риска применяются напрямую; действия с
   риском выбирают исход по своему потоку случайности. Значения треков
   зажимаются в границы, факт зажима фиксируется в записи.
6. **Динамика мира.** Правила `world_dynamics`: восстановление бюджета, спад
   напряжённости и прочее — то, что происходит независимо от команд.
7. **События.** Плановые по номеру раунда, затем триггерные по условию;
   `once: true` срабатывает один раз за партию.
8. **Конец и счёт.** Проверка `end.when`, подсчёт очков по `end.scoring` плюс
   выполненные цели.

### Случайность

Глобального генератора нет. Каждый бросок получает свой поток:

```
rng = Random(blake2b(f"{seed}|{round}|{roll_id}").digest())
```

где `roll_id` — устойчивый идентификатор («astoria:2:cyber_op» для третьего
приказа Астории, «event:oil_shock» для события). Порядок вычислений на
результат не влияет, повторный расчёт журнала даёт те же броски.

### Видимость

Каждая запись события несёт аудиторию: `public`, `actor`, `actor_and_target`,
`host`. Из одного потока записей строятся три разные картины — экран команды,
проектор и полный отчёт ведущему — фильтрацией, а не отдельными расчётами.

Тайное действие (`visibility: secret`) по умолчанию видно только автору;
бросок по `reveal_chance` может добавить цель в аудиторию записи — тогда цель
узнаёт, кто это был.

## 8. Сессия и журнал

Файл сессии — JSON:

```json
{
  "format": 1,
  "scenario": { "id": "meridian", "sha256": "..." },
  "seed": 20260901,
  "created_at": "2026-09-01T10:00:00",
  "factions": [ { "id": "astoria", "team": "Команда 1", "code": "4821" } ],
  "rounds": [
    {
      "n": 1,
      "orders": {
        "astoria": [
          { "action": "cyber_op", "target": "borea", "intent": "свободный текст замысла" }
        ]
      },
      "deals": [ { "from": "astoria", "to": "caldera", "type": "transfer", "amount": 20 } ],
      "narration": { "public": "...", "private": { "astoria": "..." } },
      "resolved_at": "2026-09-01T10:12:00"
    }
  ]
}
```

Журнал хранит **входы** (приказы, сделки) и **внешние недетерминированные
решения** (сгенерированные тексты). Состояние не хранится: оно получается
пересчётом всех раундов от начального состояния сценария.

Следствия:

- **Откат раунда** — удаление последней записи и пересчёт.
- **Воспроизводимость** — тот же файл всегда даёт то же состояние; тексты
  берутся из журнала, а не генерируются заново.
- **Переносимость** — партия это один файл, его можно переслать.
- **Контроль целостности** — `sha256` сценария в журнале; если YAML изменился,
  открытие старой партии предупреждает, что расчёт больше не совпадает.

Расположение данных: `~/Library/Application Support/StrategicGame/`
(`sessions/`, `scenarios/`, `config.json`). Внутрь `.app` ничего не пишется.

## 9. Веб-интерфейс

FastAPI, Jinja2, серверный рендеринг, немного ванильного JS. Никакой сборки
фронтенда — иначе `.app` перестанет быть самодостаточным. Язык интерфейса —
русский.

### Экраны

**Пульт ведущего** (`/`). Создание сессии: выбор сценария, число команд, seed.
Ход игры: номер раунда, список команд со статусом сдачи, крупная надпись «кому
передать компьютер», кнопка «Закрыть раунд» (активна, когда сдали все), кнопка
«Откатить раунд». Если время пары поджимает, ведущий может закрыть раунд
принудительно: несдавшие команды пасуют, пас записывается в журнал как пустой
приказ. После конца игры — переход к разбору.

**Экран команды** (`/team/{id}`). Вход по четырёхзначному коду. Содержимое:

- обстановка: свои треки полностью, чужие — только видимое;
- новости прошлого раунда в редакции этой команды, включая причины отклонения
  их приказов;
- брифинг и цели — только свои;
- каталог действий карточками: недоступные показаны серым с причиной;
  счётчик очков действий; поле свободного текста замысла к каждому приказу;
- дипломатия: предложить сделку, ответить на входящие;
- кнопка «Сдать приказы» с подтверждением.

Черновик приказов сохраняется на сервере при каждом изменении: закрытая по
ошибке вкладка не теряет работу команды. После сдачи серверная сессия команды
закрывается, возврат назад ничего не показывает.

**Проектор** (`/screen`). Публичная сводка раунда, мировые треки, публичные
треки сторон, таймер раунда. Обновляется сам.

**Разбор** (`/debrief`, этап 2 для экспорта). Таймлайн, графики треков,
по каждой команде: заказано — получено — отклонено, замысел рядом с
результатом, разложение итогового счёта.

### Защита от подглядывания

Код команды, экран-заглушка по кнопке «Скрыть» и по минуте бездействия,
очистка экрана сразу после сдачи. Это защита от случайного взгляда, не от
злоумышленника — модель угроз здесь именно такая.

## 10. Нарратив и LLM (этап 2)

Контракт нарратора: на входе список записей событий и состояние, на выходе
текст. Реализаций две — шаблонная и LLM — за одним интерфейсом. Шаблонная
работает всегда и является фолбэком.

**Правило изоляции.** Для каждой аудитории делается отдельный вызов, и в него
кладутся только видимые ей записи. Тайное не утекает потому, что этих данных
нет в запросе, а не потому, что модель попросили молчать.

**Числа неприкосновенны.** LLM получает уже посчитанные дельты и пересказывает
их. Ответ не парсится обратно в состояние.

**Кэширование в журнал.** Сгенерированный текст сохраняется в запись раунда.
Пересчёт партии не обращается к сети и даёт тот же текст.

**Распознавание намерения.** Свободный текст команды отправляется вместе с
каталогом доступных действий; ответ — структурированный приказ, который
показывается команде на подтверждение. В журнал уходит подтверждённый приказ,
а не текст. Ядро остаётся единственным источником чисел.

**Настройки.** Модель по умолчанию `claude-opus-5`, адаптивное мышление,
официальный SDK `anthropic`. Ключ вводится в интерфейсе и хранится в
`config.json` пользовательской директории; переменная окружения — запасной
путь. Без ключа приложение работает полностью, на шаблонах, и говорит об этом
одной строкой в настройках, а не ошибкой.

## 11. Поставка

**Основной канал.** PyInstaller в режиме onedir собирает `.app`, который
запускает локальный сервер на свободном порту и открывает браузер. Архив плюс
инструкция на одну страницу, включая обход Gatekeeper при первом запуске
(правый клик → «Открыть»). Подпись и нотаризация не делаются: это требует
Apple Developer Program за 99 $ в год и на текущем масштабе не окупается.

**Второй канал.** Тот же проект ставится как обычный пакет
(`uv tool install` / `pip install`) и запускается командой `sgame run`. Это
режим разработки и путь для технических пользователей.

**Ограничения, которые это накладывает на код:** только чистый Python;
шаблоны, статика и сценарии подключаются как ресурсы пакета через
`importlib.resources`; пути к данным — только через `session/paths.py`.
Соблюдение этих трёх правил делает сборку под Windows прогоном того же
скрипта на Windows-машине.

## 12. Тестирование

Разработка через тесты: сначала тест, потом код.

**Ядро.** Юнит-тесты на каждую фазу; на вычислитель выражений (включая отказ
исполнять недопустимые конструкции); на валидатор — по тесту на каждый из
шести классов ошибок; на зажим треков по границам.

**Золотые прогоны.** Сценарий, seed и записанные приказы дают зафиксированный
журнал в `tests/golden/`. Любое изменение баланса или формул сразу видно в
диффе — это основной инструмент против незаметной поломки модели.

**Свойства.** Пересчёт журнала с нуля даёт то же состояние. Откат раунда с
последующим повтором тех же приказов даёт то же состояние. Порядок сторон в
приказах не влияет на результат.

**Веб.** Отдельная группа тестов на видимость: команда не получает ни в HTML,
ни в JSON ничего, что ей не адресовано. Это главный функциональный риск игры с
тайными приказами.

**LLM.** В тестах заменяется заглушкой. Сетевых тестов в наборе нет.

## 13. Нефункциональные требования

- Расчёт раунда — меньше секунды на 6 команд: пауза на занятии недопустима.
- Приложение полностью работоспособно без интернета.
- Интерфейс на русском языке.
- Одновременно открытые вкладки пульта, команды и проектора не конфликтуют.

## 14. Критерии готовности этапа 1

1. Партия на 4 команды и 8 раундов проходится целиком без ошибок.
2. Тест подтверждает, что команда не видит чужих приказов, чужих приватных
   треков и чужих брифингов.
3. Откат раунда возвращает ровно то состояние, что было до него.
4. `sgame validate` находит все шесть классов ошибок сценария и печатает
   номера строк.
5. Золотой прогон зафиксирован и проходит.
6. Собранный `.app` запускается на другом Mac по приложенной инструкции.
7. Эталонный сценарий «Кризис в Меридианском заливе» заполнен: 4 стороны,
   не менее 12 действий, не менее 6 событий, тайные брифинги и цели.
